# Context Hub contribution roadmap

**Status:** active governed delivery plan  
**Endpoint:** a useful multi-agent attention instrument with exact receipts, human admission, rollback and identity-preserving federation; never an autonomous truth or corpus authority

## Gate ledger

| Gate | Current state | Completion test |
|---|---|---|
| Live local beacon | closed | MCP and `/api/beacon` expose the same invitation and authority boundary. |
| Direct contribution inbox | closed locally | An agent can submit without an episode, receive an immutable receipt and inspect a non-admitting disposition. |
| Retrieval identity stability | closed | Two serial and two parallel clean-process 30-case runs match the retained content, evidence-projection and baseline identities exactly at MRR 0.925. |
| Protected read-only MCP | open; carrier/adapter decision isolated | A fresh Sourcery connection discovers and executes every operation against a revision-pinned corpus without mutation authority. See [`protected_admission_preflight_v1.json`](protected_admission_preflight_v1.json). |
| Real longitudinal evaluation | warm-up gate closed; independent longitudinal gate open | The retained 12-case warm-up passes all engineering gates; preregistered independent tasks must still compare baseline and adaptive attention over multiple turns. |
| Protected Observatory identity | open | A separately named write-capable application passes persistence, authentication, approval, rollback, freeze, recovery and drift controls. |
| Agent-facing work ecology | closed locally | Opportunities, dependency declarations, exclusive claims/releases, attribution, dispositions and downstream-impact receipts share one append-only contribution chain without admission authority. |
| Identity-preserving federation | all six repository-snapshot lanes closed locally; live refresh and protected delivery open | Canonical corpus, Claimipedia claims, Sourcery derivations, publication, experiment artifacts and dated external literature retain native object, revision, status and relation identity under positive and negative fixtures. |
| Mature collective instrument | open | Longitudinal utility improves without evidence multiplication, concentration, capture or loss of complete replay. |

## Delivery order

1. Stabilize retrieval identity and generated-surface ordering.
2. Seal the read-only search/context/beacon capability through Sourcery.
3. Exercise the direct inbox with external agent packets and human dispositions.
4. Run baseline-versus-adaptive episodes using independent task outcomes, not corpus-marker self-confirmation.
5. Admit the state-owning Observatory separately; never smuggle write authority through the read-only MCP.
6. Connect canonical corpus and publication first, then Claimipedia and Sourcery, and external literature last.
7. Measure longitudinal benefit, uncertainty, diversity, adverse evidence, rollback and capture resistance.

## Hard boundaries

- Attention utility is objective-scoped and is not truth probability.
- Inbox acceptance is acknowledgement, not admission to an attention state.
- An approved attention update cannot change source status or corpus content.
- One causal evidence family produces at most one effective update per source.
- No cross-objective transfer, reusable prior or shared learning is allowed without a separately qualified design.
- No lane may gain promotion authority by federation, popularity or graph centrality.
- Human purpose remains external to the estimator.

## Current architectural frontier

The local search implementation reads a live repository on Windows, while the protected Sourcery runtime is a separate Linux-hosted, algebra-first system that forbids opaque new executable callbacks. Protected admission therefore needs an explicit revision-pinned corpus carrier or a mature read-only adapter; simply copying the local JavaScript into a runtime lane would violate both deployment reality and the current algebra-first policy. This is the principal engineering decision at the read-only admission gate.
