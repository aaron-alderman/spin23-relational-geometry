## Investigation and implementation

The preceding seven-sample/500-iteration observation of about 5% slower ordinary evaluation was too small to establish a general regression. The extended mixed-variant baseline can place identical before/current code more than 10% apart, demonstrating method/JIT variation. The fresh-process runs therefore admit one evaluator per timed call site, use 5,000 warmups, eleven samples of 3,000 evaluations and three counterbalanced process trials per variant. Scalar, 20-field record, 20-item list and lexical fixtures retain raw timings. `before-index.mjs` is the exact pinned predecessor with only static import/export specifiers adapted; hashes are in `before-index-identity.json`. The original 5bcde83 kernel is also retained as an older reference. These runs are one evidence family, not independent confirmations or a universal threshold.

Separate-process ratios remained very noisy. `paired-canonical.mjs` therefore uses distinct monomorphic lexical call sites within one process, counterbalanced batches, 20,000 warmups and 45 observations of 3,000 evaluations, repeated in three processes. Geometric means of the per-process median candidate/predecessor wall ratios are 0.974 scalar, 0.986 record, 0.967 list and 0.978 lexical: roughly 1.4–3.3% lower fixture medians. Individual sample variation is much wider; this does not certify a general speedup percentage or statistical significance. CPU counts are retained, but Windows counter granularity produces zero/coarse values at short batch sizes, so no CPU reduction percentage is claimed. See `paired-canonical-summary.json` and all raw observations. These CPU workers finish before application samples; they may overlap untimed graph materialization.

The ordinary evaluator previously allocated continuation and ordered-entry closures on every recursive visit, although most operations never used them. It now passes its existing source directly to the shared operation implementation and performs context recursion or ordered-entry work only when the reached operation requires it. Prepared evaluation still supplies its private callbacks. The operation implementations, admission rules, live graph lookups, validation, trace handling, fault behavior and public allocation semantics remain shared and unchanged in intent. No ordinary memoization, generated code, runtime module or dynamic import site is introduced.

Seven added assertions inside the existing live-provider test group verify changing ordinary graph values, exact ordered-entry lookup order and lexical binding/context preservation. Every previous assertion remains. All 111 algebra checks and 41 focused SDK protocol/translation checks passed. The managed source run passed 2,336 platform checks plus 11 supplemental policy/helper checks and a separate complete 111-check algebra run. Existing source titles and multiplicities must remain exact. The repeated imported/delegated library executions are not separate evidence families.

The fixed auth clock removes expiry drift. All pinned source bytes are checked again after the measurements.

These are local sequential warm-filesystem engineering measurements with raw distributions, including median and nearest-rank p95. Startup means a fresh module process with warm filesystem caches, not a reboot/cold disk. HTTP includes the client, loopback transport and body consumption. Auth measures the public API and real storage, not a fabricated product login endpoint.
