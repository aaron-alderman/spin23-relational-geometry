# Corpus front door

> The corpus front door is an executable atlas of the interior: every assertion resolves to an exact retained object, and every retained object is either reachable from a declared entrance or explicitly classified.

This is a generated atlas, not a claim of truth or completeness. Its machine-readable twin is [`registers/corpus_front_door.json`](registers/corpus_front_door.json); its declared roots live in [`front-door.routes.json`](front-door.routes.json). Drill down from those roots to exact corpus objects, then use the [canonical file manifest](registers/spin23_corpus_manifest.json) for path, byte and hash identity.

**Authority boundary.** This atlas reports repository structure and declared epistemic surfaces. It does not promote claims, replace source evidence, or grant publication, corpus-admission, runtime, or deployment authority.

**Coverage.** 16 declared roots across 4 routes; 6022 retained inventory objects; 4623 objects reachable through local links; 6022 objects explicitly classified; 0 unclassified. The atlas passes its structural checks.

## Structural contract

The generator fails its admission check when a declared root is missing, lacks epistemic status/authority/provenance, contains a broken direct local link, references an unknown profile root or required path, or leaves an inventory object unclassified. Broken links deeper in the closure remain visible in the machine diagnostics because historical material can contain intentionally unresolved or externally restored references.

Regenerate or check from the repository root:

```powershell
node tooling/indexing/generate_corpus_front_door.mjs --write
node tooling/indexing/generate_corpus_front_door.mjs --check
node --test tests/repository/corpus_front_door.test.mjs
```
