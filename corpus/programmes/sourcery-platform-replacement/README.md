# Sourcery platform replacement

This programme records the staged migration of the non-application Sourcery platform and shell from mixed MJS policy into algebra-owned Git sources with a minimal imperative kernel.

The [replacement map](platform-git-replacement-map-v1.json) is an inactive architecture and sequencing record. It maps the accepted Git owners, proposes the independently versioned `sourcery-kernel`, `sourcery-platform` and `sourcery-shell` owners, catalogues the platform domains, and defines the audit, extract, collate and collapse phases.

The map does not create repositories or grant source merge, package adoption, runtime activation, writer handover, legacy retirement or publication authority. Exact source observations remain linked to their immutable bases. Temple snapshots and the ignored local migration records are evidence inputs, not replacements for Git provenance.

The [source-discovery checkpoint](source-discovery-checkpoint-v1.json) records the first tranche's current mechanism gap: the serving generation exposes only the unbounded workspace inventory, while the bounded, source-identity-preserving successor is qualified but inactive. It retains the exact successor evidence and assigns its eventual semantics and adapter to the proposed Git owners without retrying the refused Temple promotion path.

The [platform-shell extraction checkpoint](platform-shell-extraction-checkpoint-v1.json) reconciles seven already-merged semantic extraction lanes. It records their exact source-lane heads while explicitly withholding file-closure, Git-receiving, adoption and retirement claims until bounded discovery can provide path/hash drill-down.

The [MJS audit schema](mjs-audit-schema-v1.json) defines the function-level evidence needed for the first phase: exact Git or Temple source identity, entrypoint reachability, static and dynamic edges, semantic coordinates, effects, disposition, witnesses, Seams, symmetry breaks and unresolved residuals.

The [repository boundary review](repository-boundary-review-v1.json) applies the common-reduction rule to the proposed Git topology. It corrects an initial connection-scope absence error: the private `sourcery-platform` repository already exists and is the candidate canonical owner. Replacement work therefore begins as an architecture-only branch inside that repository, with strict kernel, platform and shell boundaries and no root runtime change. A package becomes an independent repository only after an independently governed lifecycle is observed.

The [repository existence correction](repository-existence-correction-v1.json) retains the failed absence inference and its containment. The existing repository refused duplicate creation; no remote mutation occurred, and the local inert bootstrap has no authority.

During migration, every material authority, custody, process, trust and external-effect crossing remains an explicit Seam. An accidental compatibility Seam becomes seamless only after all consumers have crossed, blocking residuals are closed, the legacy mechanism is unreachable at runtime and an accepted retirement witness exists.
